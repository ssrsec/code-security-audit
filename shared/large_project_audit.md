# 大项目审计约定（强制 100% 覆盖）

应审文件 >200 或单次上下文无法一次处理时，必须分批执行 阶段 2。

---

## 1. 分批策略

- 每批 50-150 文件，按模块或 Tier 切分。
- 每批必须产出：
  - `audit/phase2/findings_batch{N}.md`（候选漏洞）
  - `audit/phase2/reviewed_paths_batch{N}.txt`（审阅文件清单）
- 完成一批后将审阅路径追加到 `audit/phase2/reviewed_paths_merged.txt`。

## 2. 批次优先级

- **P0（最高）未认证可达**：白名单/公开接口/回调/文件操作/导出等
- **P1 已认证低权限可达**：普通用户可访问的敏感操作
- **P2 管理员专用**：仅在有细粒度角色差异时重点关注

## 3. 覆盖率校验与自动补扫

- 每批完成后执行 阶段 3，计算覆盖率。
- 未达 100% 则**自动执行下一批**，不停不问用户。
- 仅当平台限制无法继续时才输出断点提示。

## 4. 断点续跑

用户说「继续审计」时：
1. 读取 `audit/phase1/owasp_coverage_matrix.md` 和 `audit/phase2/coverage_status.json`
2. 从下一批继续
3. 自动循环直到 100% 再进入 阶段 4

## 5. Tier 分类

- **T1（入口层）**：Controller/Handler/路由/Filter → 完整深度分析
- **T2（业务层）**：Service/DAO/中间件/配置 → 先筛后读
- **T3（数据层）**：Entity/VO/DTO/Model → 模式匹配，发现非简单数据类可提升到 T2


## 6. 强制进度与产出可见性（绝对精确，严禁估算）
- **禁止使用“估算”、“约”等模糊词汇**：覆盖率必须是绝对精确的数学计算，即：`已审阅文件总数 / 应审文件总数 * 100%`。
- **强制公式与精确输出**：每次批次扫描结束或中断时，你必须通过 wc -l 或严格计数统计 `in_scope_files.txt`（分母）和 `reviewed_paths_merged.txt`（分子）的具体行数。输出必须是明确的数字，例如：“当前审计进度：已审阅 150 个文件 / 共 300 个应审文件，精确覆盖率为 50.0%”。
- **强制要求用户输入继续审计**：只要精确覆盖率没有达到 100%，系统在本次会话耗尽前必须通过文本明确告诉用户：“当前审计进度为 X%，仍有 Y 个文件未审计，请发送『继续审计』以完成剩余部分。”
- 只有精确覆盖率达到 100% 并走完所有的阶段（直到 阶段 6 报告生成），才能宣告审计完成。绝对禁止在没跑完的情况下欺骗用户“审计完成”。


## 7. 绝对阶段隔离与禁止提问多选
- **禁止阶段混杂**：在 `阶段 3` 计算出的精确覆盖率没有达到 `100.0%` 之前，**严禁触碰或提前执行** `阶段 4`、`阶段 5`、`阶段 6` 的任何工作。绝对不允许出现“批次X + 阶段4部分完成”的情况。
- **禁止提供捷径选项**：在任何中断点，**绝对禁止**询问用户“是否要提前生成报告”或“是否要深挖某个漏洞”。只要覆盖率没满，对用户的回应必须明确说明：“当前审计进度为 X%，仍有 Y 个文件未审计，请发送『继续审计』以完成剩余部分。”
