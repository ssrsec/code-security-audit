# 最终报告字段定义

最终报告 `audit/security_audit_report.md` 必须能被研发、安全和管理人员独立阅读，不依赖 LLM 记忆。报告可以引用 `audit/final/` 证据包，但关键结论、漏洞证据、验证结果和修复建议必须在报告中直接呈现。

## 1. 报告顶级结构

推荐使用以下 8 个顶级章节：

1. 项目代码审计总结
2. 项目基础架构画像
3. 审计范围与覆盖矩阵
4. 漏洞汇总表
5. 漏洞详情
6. 组合漏洞与攻击链
7. PoC/测试验证结果
8. 总体安全建议与残余风险

## 2. 项目代码审计总结

| 字段 | 说明 | 必填 |
|------|------|------|
| 审计目标 | 项目名称、路径、commit/版本（如可获取） | 是 |
| 审计模式 | source_only / compiled_only / both | 是 |
| 开始时间 | 读取 `audit/phase0/metrics.md` | 是 |
| 结束时间 | 生成报告时执行 `date "+%Y.%m.%d %H:%M:%S"` | 是 |
| 文件覆盖率 | 已审 X / 应审 Y = 100% | 是 |
| 标准覆盖 | OWASP/ASVS/WSTG 覆盖摘要 | 是 |
| 发现统计 | 按严重/高/中/低、已确认/待验证、漏洞类型统计 | 是 |
| 验证统计 | V0/V1/V2/V3/V4 数量，说明哪些进入报告 | 是 |
| 重要限制 | 未覆盖项、无法验证项、环境限制 | 是 |

## 3. 项目基础架构画像

必须包含：

- 目录结构和模块职责。
- 开发语言、框架、中间件、构建系统、运行方式。
- HTTP/RPC/MQ/WebSocket/CLI/任务调度入口。
- 数据库、缓存、对象存储、文件系统、搜索引擎、第三方 API。
- 认证逻辑：登录、SSO/OAuth、JWT/session、token 存储和生命周期。
- 授权逻辑：RBAC/ABAC/ACL、自定义权限、资源归属、多租户隔离、拦截器。
- 依赖与供应链：关键依赖、锁定版本、已知漏洞、gadget 线索。
- 信任边界和高价值资产。

## 4. 审计范围与覆盖矩阵

必须包含：

- 文件覆盖率：`已审 X / 应审 Y = 100%`。
- 模块覆盖表。
- OWASP ASVS/WSTG/Top 10/CWE 覆盖摘要。
- 不适用项和原因。
- 未覆盖项、限制和残余风险。

## 5. 漏洞汇总表

| 字段 | 说明 |
|------|------|
| 漏洞编号 | `WB-001`、`WB-002` 等 |
| 漏洞名称 | 标准漏洞名称 |
| 严重性 | 严重 / 高 / 中 / 低 |
| 验证状态 | 已确认 / 待验证 |
| 验证等级 | V1 / V2 / V3 / V4 |
| CWE | CWE 编号 |
| OWASP | Top 10 / ASVS / WSTG 映射 |
| 访问权限 | 无需认证 / 普通用户 / 管理员 / 特定角色 |
| 影响资产 | 数据、权限、主机、租户、文件等 |

## 6. 漏洞详情字段

每条漏洞必须包含：

| 字段 | 说明 |
|------|------|
| 漏洞编号 | `WB-XXX` |
| 漏洞名称 | 标准漏洞名称，不混入 HTTP 方法和等级 |
| 漏洞描述 | 原理、影响、为什么构成安全边界突破 |
| 严重性 | 严重 / 高 / 中 / 低 |
| 验证状态 | 已确认 / 待验证 |
| 验证等级 | V1/V2/V3/V4，V0 不进入漏洞详情 |
| CWE / OWASP | CWE、Top 10、ASVS/WSTG |
| CVSS | 完整向量、分数、指标理由 |
| 前置条件 | 网络、账号、配置、业务数据等 |
| 访问权限 | 明确角色或权限，不写模糊描述 |
| 影响资产 | 具体数据、权限、系统资源 |
| 调用链 | 每一跳 `文件:行号` |
| 代码证据 | 来自实际 Read 的简短证据摘要 |
| 待验证内容 | 仅待验证漏洞需要，列出具体未确认项 |
| PoC/测试 | 请求、脚本或测试路径、命令、预期与实际结果 |
| 修复建议 | 具体文件、修改点、修复原理、回归测试建议 |
| 残余风险 | 修复后仍需关注的部署或配置条件 |

## 7. PoC/测试要求

- 有用户测试环境时，优先输出 V4 端到端验证：请求、响应、账号权限、预期、实际、清理。
- 无测试环境时，输出 V2/V3：最小单元测试、集成测试、mock 验证或本地运行说明。
- PoC 必须无害、可清理、可复现。
- HTTP 漏洞可提供 Burp/HTTP 格式数据包；非 HTTP、多步骤或复杂协议提供完整脚本或测试用例。
- 可以使用 `{{access-token}}` 等运行时变量，但必须在前置步骤给出获取方式；不得使用 `REPLACE_XXX`、`此处从略`、`TODO`、省略号等空洞占位。
- 破坏性行为必须替换为无害证明或在授权测试环境中说明回滚步骤。

## 8. 组合漏洞与攻击链

每条组合漏洞包含：

| 字段 | 说明 |
|------|------|
| 组合编号 | `CHAIN-001` |
| 涉及漏洞 | `WB-001 + WB-003` |
| 攻击链 | 逐步说明从初始入口到最终影响 |
| 组合后等级 | 严重 / 高 / 中 / 低 |
| 验证等级 | V1-V4 |
| 限制 | 未验证条件或环境限制 |
| 修复优先级 | 应先修哪个根因 |

若无组合漏洞，写明“经分析，未发现可组合利用的漏洞链”，并简述分析范围。

## 9. 总体安全建议与残余风险

必须覆盖：

- 架构层面加固：认证、授权、租户、网关、服务间信任、密钥管理。
- 开发流程改进：安全编码规范、Code Review、SAST/SCA/Secret、测试门禁。
- 高频漏洞类型的统一修复方案。
- 依赖升级和供应链治理。
- 回归测试和修复验证建议。
- 未覆盖项、待验证项和残余风险。

## 10. 准入检查

进入最终报告前逐条检查：

- 文件路径和行号已实际读取验证。
- 调用链闭环或明确待验证断点。
- CWE/OWASP/CVSS 映射完整。
- PoC/测试命令、预期、实际、清理步骤完整。
- 触发条件不成立的 finding 已进入 rejected，不在漏洞表中出现。
- 报告中的限制和残余风险没有被隐藏。
